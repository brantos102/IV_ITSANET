1. Obtener y cargar el JSON real

El JSON del monitor contiene eventos de procesos. No es un archivo Excel convertido a JSON ni contiene el tiempo total que tarda un operario en contar. La presentación utiliza duracionMs de los intentos FOTO COPIADA para calcular sus percentiles.

Opción A: navegador con sesión ADMIN

  • Entrar a https://apps.flexnetuio.com:8443/app/ con la cuenta ADMIN autorizada.
  • Abrir en otra pestaña: https://apps.flexnetuio.com:8443/api/operacion/procesos?limite=100 . No escribir credenciales en la URL.
  • Si devuelve JSON, guardar con Ctrl+S como monitor.json (archivo completo). Alternativa: F12 → Red/Network → abrir el monitor → seleccionar procesos → Copiar respuesta y guardar como texto UTF-8 con extensión .json.
  • No guardar ni compartir un HAR, cabeceras, cookies o tokens. Si devuelve 401/403, revisar sesión/rol; no desactivar controles.
  • En la diapositiva Rendimiento observado, pulsar Seleccionar archivo y elegir monitor.json. Se procesa localmente. El monitor devuelve solo una muestra limitada de eventos recientes.

Opción B: periodo definido desde VS Code conectado al servidor

Descomprimir el paquete en el PC. En el Explorador de VS Code remoto, crear /home/enicolalde/bryan/medicion-IV-ITSANET y cargar allí únicamente exportar_mediciones_presentacion.py. No reemplazar archivos de la aplicación.

cd ~/bryan/IV_ITSANET
sudo systemd-run --quiet --wait --pipe --collect \
  --unit="iv-itsanet-medicion-$(date +%s)" --uid="$(id -un)" \
  --property="WorkingDirectory=$PWD" \
  --property=EnvironmentFile=/etc/iv-itsanet.env \
  "$PWD/.venv/bin/python" \
  "$HOME/bryan/medicion-IV-ITSANET/exportar_mediciones_presentacion.py" \
  --desde "2026-10-28T08:00" --hasta "2026-10-28T18:00" \
  --salida "$HOME/bryan/medicion-IV-ITSANET/mediciones-20261029.json"

Cambiar las fechas al intervalo real: hora Ecuador, inicio inclusivo y fin exclusivo; máximo 31 días. Confirmar el WorkingDirectory si el servicio usa otra ruta. Se crea un proceso transitorio de exportación con el entorno protegido y el usuario de la terminal; no reinicia iv-itsanet, Apache ni MySQL. El script abre una transacción SQL READ ONLY, aplica límite/timeout y escribe solo el JSON indicado con permiso 0600. No sobrescribe un archivo existente.

En el Explorador remoto de VS Code: clic derecho sobre el JSON → Descargar. Cargarlo en la diapositiva. Si truncado=true, reducir el periodo; no presentar la muestra como el total. Una carga pesada puede consumir recursos de lectura: usar periodos pequeños fuera del pico.

2. Qué representan los tiempos y cómo compararlos

MediciónInterpretación
FOTO COPIADA / duracionMsDuración del intento exitoso de verificación/copia/organización. Excluye captura, espera en cola y el ciclo completo de recepción.
Mediana y P95Percentil por rango más próximo sobre intentos válidos; no son garantía de velocidad ni tiempo máximo.
Reintentos / organizaciónUn mismo archivo puede generar varias operaciones exitosas; el tamaño de muestra cuenta intentos, no fotos únicas.
Errores y ventanasEl exportador incluye eventos de foto/correo, pero los percentiles usan solo FOTO COPIADA con duración válida. Reportar sesgo y periodo.
Conteo / correo completoNo existe un cronómetro integral acreditado en el código para todo el flujo. Medir inicio/fin con protocolo homogéneo.

Para comparar revisiones anteriores, completar la plantilla CSV incluida: tarea, registros, minutos anteriores, minutos actuales, personal y condiciones. Usar comas como separador y evitar comas o saltos de línea dentro de los textos de esta plantilla simple. Conservar los inicios/finales y evidencia del cronometraje por separado. Medir la misma tarea, volumen y criterio de término. Separar conteo, evidencia y elaboración de informe. Los minutos también pueden ingresarse manualmente en la diapositiva; la fórmula no prueba causalidad.

3. Preparar la demostración real en móvil o handheld

  • Elegir un entorno de pruebas con SQL y carpeta Drive separados. Si se demuestra en producción, obtener autorización para una recepción claramente identificada de demostración, sin reutilizar recepciones/correos de clientes. Guardar una demo sí escribe datos.
  • Preparar cuenta OPERADOR y cuenta SUPERVISOR/ADMIN separadas. Usar un SKU y packing de prueba concordantes. No mostrar contraseñas al público.
  • Conectar el dispositivo a la red autorizada y abrir https://apps.flexnetuio.com:8443/app/ en Chrome compatible. Verificar certificado confiable y permiso de cámara. No omitir alertas TLS.
  • Entrar con el operario, seleccionar recepción y Validar. El escáner físico debe enviar el código como teclado al campo de lectura; comprobar el sufijo Enter si el equipo lo requiere.
  • Alternativa: pulsar Cámara para leer el código. El lector usa BarcodeDetector cuando está disponible y respaldo ZXing local. Escanear solo consulta; el conteo se guarda al pulsar Guardar conteo.
  • Registrar cantidad/pallet/posición y condición. Para PNC, registrar la cantidad afectada y observación; adjuntar la foto de la mercadería en Fotos para este conteo o el flujo de evidencia correspondiente.
  • Guardar y revisar bitácora. En supervisión comprobar las unidades, PNC, estado de copia Drive y enlace; luego revisar el informe y sus adjuntos. No enviar un correo real de cliente durante la demo.

4. Mostrar el dispositivo en vivo al público

La presentación dispone de un botón que abre la URL real en otra pestaña. El HTML descargado no puede reflejar por sí solo la pantalla autenticada de otro dispositivo ni habilitar la cámara de ese handheld.

AlternativaUso y límite
Compartir pantalla desde el móvilUtilizar la herramienta corporativa aprobada (por ejemplo, compartir pantalla en la reunión desde Android). Iniciar sesión antes y ocultar notificaciones; compartir solo lo necesario.
Duplicación por hardwareHDMI/USB-C o proyección compatible, si el handheld y la política de equipos lo permiten. No todos los equipos soportan salida de video.
PC en modo móvilChrome F12 → barra de dispositivos permite mostrar el diseño responsive. No acredita el lector físico ni la cámara del handheld real.
Depuración por USBSolo mediante un procedimiento aprobado para el equipo; no se necesita activarla para el uso operativo normal.

Guion breve: lector físico → ficha del SKU → cantidad/ubicación → novedad PNC → fotografía → guardado → bitácora → revisión del supervisor. Si la cámara falla, consultar /app/diagnostico-camara.html, permisos y certificado; conservar los registros ya guardados.

5. Capturas y privacidad durante la exposición

La galería incorporada contiene capturas de interfaz obtenidas previamente en pruebas con datos sintéticos (v64/v69). Están etiquetadas como pruebas. Las capturas actuales pueden cargarse desde el botón local de la presentación; no se publican ni se incorporan automáticamente al HTML descargado.

Antes de cargar capturas actuales, ocultar datos de personas, correos, clientes y elementos ajenos a la finalidad. Las imágenes se mantienen en memoria de la página y se descartan al recargar. No enviarlas al repositorio sin revisión. El paquete no contiene contraseñas, tokens ni JSON productivo.
