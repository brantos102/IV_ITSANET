Continuidad del conteo ante cortes de conexión

Guía de operación y recuperación. Los cambios se utilizan después del pase controlado de la versión 71.

Guarda cada conteo, aunque se corte la red

  1. Entra con conexión y abre la recepción para descargar sus lecturas.
  2. Escanea un código descargado, escribe la cantidad y ubicación, registra la novedad y adjunta fotos.
  3. Pulsa Guardar conteo. El aviso Conteo pendiente de sincronizar confirma respaldo en el dispositivo. Puedes continuar con el siguiente conteo.
  4. Consulta Respaldo de conteos en este dispositivo. Mantén la aplicación abierta cuando vuelva la conexión.
  5. Pendiente sincronizado confirma el servidor. Los indicadores solo incluyen cantidades confirmadas.
  6. Si el trabajo requiere revisión, abre Revisar pendientes. Conserva el registro y resuelve el mensaje antes de reintentar.
Si el respaldo falla por falta de espacio, la ficha permanece abierta y muestra el error. No cierres ni borres sus datos. Mantén el mismo navegador, perfil y URL.

Conservación y rescate

Descargar respaldo guarda un JSON con registros, fotografías e IDs originales. Restaurar respaldo permite recuperarlos con la misma cuenta; no se duplican los IDs ya recibidos. La aplicación cerrada conserva la cola, pero no ejecuta envíos hasta volver a abrirla. Para una nueva autenticación hace falta el servidor.

Revisa excepciones y confirma antes de cerrar

  • Sin conexión no llegan presencias ni conteos nuevos de otros dispositivos. Coordina los pallets físicos para evitar repetir las mismas unidades.
  • Un sobrante detectado al reconectar exige confirmación explícita. El sistema no inventa la aprobación.
  • Un reparto desactualizado debe revisarse contra el total vigente. La propuesta original se conserva.
  • Si una recepción ya está cerrada, el pendiente queda en revisión. Resolver el cierre antes de reintentar; el sistema no reabre la recepción automáticamente.
  • Antes de cerrar, comprueba que todos los equipos hayan sincronizado. El servidor no puede mostrar una captura que permanece exclusivamente en un equipo desconectado.
Los pendientes se mantienen por cuenta. No cambiar de usuario para intentar enviarlos. Un respaldo del servidor no incluye los registros que aún no salieron del dispositivo.

Confirmación durable e idempotencia

1 · PENDIENTEIndexedDB confirma payload, cuenta, recepción, clave original y binarios de fotos. La ficha puede liberarse.
2 · ENVIANDOSe verifica la sesión. Se suben las fotos y se guardan sus enlaces localmente antes de publicar el conteo.
3 · CONFIRMADOEl ACK del servidor se persiste. Solo entonces se liberan los binarios locales. Una respuesta perdida reusa la misma clave.
REVISIONSobrante, cierre, permiso, destino o reparto requieren decisión. Se conserva el trabajo y no se fuerza ni descarta.

La cola usa un arrendamiento atómico por registro para coordinar pestañas. El servidor mantiene sus bloqueos de fila y control de idempotencia. Los reintentos tienen espera progresiva y también se activan al volver la red. No depende de Background Sync.

La fecha del dispositivo es informativa; la fecha de registro del servidor se mantiene. No se añade una tabla MySQL ni se reconfigura Apache. Se mantienen la cola de copia a Drive y sus verificaciones independientes.

Límites que deben conocerse

Los indicadores desconectados son la última copia confirmada. No se resuelven códigos desconocidos o ambiguos sin red. No se eliminan pendientes por antigüedad. Un borrado del navegador, daño o pérdida del dispositivo no puede recuperarse desde el servidor si el trabajo no llegó ni se exportó.
